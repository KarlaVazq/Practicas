## Paso 2: actualiza el modelo
Crea o modifica el modelo `Producto` en:

```text
demo/src/main/java/com/example/demo/model/Producto.java
```

```java
package com.example.demo.model;

import java.math.BigDecimal;
import java.time.LocalDate;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@NoArgsConstructor
@AllArgsConstructor
@Data
@Table(name = "producto")
@Entity
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nombre;
    private String descripcion;
    private String lote;
    private BigDecimal precioUnitario;
    private LocalDate fechaCaducidad;
}
```

> Nota: eliminamos los getters y setters, pero agregamos dos anotaciones: `@NoArgsConstructor` y `@AllArgsConstructor`.
>
> Revisa la anotación `@GeneratedValue` y analiza qué significa lo que está dentro de los paréntesis.

## Paso 6: agrega o edita el siguiente método
En el mismo controlador, agrega esta operación:

```java
@PutMapping("/producto/{id}")
public Producto putProduct(@PathVariable Long id, @RequestBody Producto producto) {
```

Repite el paso 5 para verificar que los cambios se hayan realizado correctamente.

## Resolución del ejercicio

**Entregables (`demo/`):** `model/Producto.java`, `repo/ProductoRepo.java`, `producto/ProductoController.java`, `application.properties` y `pom.xml`.

**Paso 1: base de datos.** Se crean el usuario y la base `chochos` con los comandos del README. En `application.properties` la conexión usa `chochos`/`chochos` (credenciales de práctica, solo para desarrollo local).

**Paso 2: `@GeneratedValue`.** `strategy = GenerationType.IDENTITY` indica que el identificador lo genera la base de datos con una columna autoincremental (en PostgreSQL, `bigint generated by default as identity`). Por eso el JSON del `POST` no lleva `id`, y el primer producto recibe `1`, el siguiente `2`, etc. Es distinto de `GenerationType.UUID`, donde la aplicación genera un identificador de texto.

**Pasos 3 a 9: operaciones**

| Paso | Endpoint | Resultado esperado |
|---|---|---|
| 4 | `POST /producto` | Devuelve el JSON del producto con `id` (`1` la primera vez). |
| 5 | `GET /producto/1` | Devuelve el producto "Creatina". |
| 7 | `PUT /producto/1` | Devuelve el producto con los datos nuevos ("Proteína de fresa", caducidad `2027-06-07`). |
| 9 | `DELETE /producto/1` | Devuelve `{"success":true}`; `GET /productos` ya no lo incluye. |

El `PUT` asigna el `id` de la ruta al objeto recibido antes de guardar. Con `save`, JPA actualiza el registro si ya existe ese `id`.

**Observación:** con `Optional`, un `GET` de un `id` inexistente responde `200` con cuerpo vacío en lugar de `404`; la práctica de códigos HTTP corrige este comportamiento.
